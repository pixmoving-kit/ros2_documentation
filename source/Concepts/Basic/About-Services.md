# 服务

在ROS 2中,一个服务指的是远程程序调用。换句话说,一个节点可以向另一个节点调用远程程序,从而进行计算并返回结果。

这种结构体现在服务消息定义的外观:

``` default
uint32 request
---
uint32 response
```

在ROS 2中,由于客户端一般在等待结果,预计服务会很快返回。服务永远不应用于较长运行的流程,特别是可能需要在例外情况下先行处理的流程。如果服务将进行长期计算,请考虑使用一个程序。 [动作](About-Actions.md) 换句话说。

服务由服务名称来识别,它看起来很像一个主题名称(但名称空间不同).

一个服务由两个部分组成:服务服务器和服务客户端.

<span id="service-server"></span>

## 服务服务器

一个服务服务器是接受远程程序请求并进行一些计算的实体。例如,假设ROS 2 消息包含以下内容:

``` default
uint32 a
uint32 b
---
uint32 sum
```

服务服务器是接收此信件的实体, 添加 `a` 财务报告和财务报告 `b` 并返回 `sum`.

> **说明**
>
> 每个服务名称只能有一个服务服务器。 如果在同一服务名称上存在多个服务服务器, 则无法定义哪个服务服务器会接收客户端请求 。

<span id="service-client"></span>

## 服务客户端

服务客户端是一个将请求远程服务服务器代表它进行计算的实体。从上面的例子来看,服务客户端是创建包含初始信件的实体。 `a` 财务报告和财务报告 `b`,并等待服务服务器计算和返回结果。

与服务服务器不同,使用同一服务名称的服务客户端可能存在任意数量.
