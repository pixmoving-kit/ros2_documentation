# 动作

在ROS 2 中,一个动作是指一个长途远程程序呼叫,并带有反馈和取消或预先阻止目标的能力. 例如,运行机器人的高端状态机器可以要求一个动作,告诉导航子系统前往一个路点,这可能需要数秒(或数分钟)才能完成. 一路走过去,导航子系统可以提供沿途多远的反馈,高端状态机器可以选择取消或预先阻止前往该路点.

这种结构体现在动作信息定义的外观:

``` default
int32 request
---
int32 response
---
int32 feedback
```

在ROS 2中,由于在建立和监测连接方面有间接费用,预计行动会很长的运行程序。如果需要短程运行远程程序呼叫,请考虑使用 [服务](About-Services.md) 换句话说。

动作由一个动作名称来识别,这个名称看起来很像一个主题名称(但名称空间不同).

一个动作包括两个部分:动作服务器和动作客户端.

<span id="action-server"></span>

## 动作服务器

动作服务器是接受远程程序请求并在上面执行某些程序的实体。它也负责随动作的进展发出反馈,并且应对取消/优先处理请求作出反应。例如,考虑用下列接口计算Fibonacci序列的行动:

``` default
int32 order
---
int32[] sequence
---
int32[] sequence
```

动作服务器是接收此信件的实体, 开始计算序列直到 `order` (沿途提供反馈),最后返回一个完整的结果: `sequence`.

> **说明**
>
> 每个动作名称只应该有一个动作服务器。 如果在同一动作名称上存在多个动作服务器, 则未定义哪个动作服务器会接收客户端请求 。

<span id="action-client"></span>

## 动作客户端

动作客户端是一个将请求远程动作服务器代表它执行程序的实体。按照上面的例子,动作客户端是创建包含此程序的初始信件的实体。 `order`,并等待动作服务器计算序列并返回(沿途有反馈).

与动作服务器不同的是,使用同一动作名的动作客户端可能会有任意数量.
