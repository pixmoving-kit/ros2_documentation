# 动作

在 ROS 2 中，动作（action）是一种耗时较长的远程过程调用，支持提供反馈，以及取消或抢占目标。
例如，控制机器人的高层状态机可以调用一个动作，让导航子系统移动到某个航点；这可能需要数秒甚至数分钟。
在移动过程中，导航子系统可以反馈进度，而高层状态机可以选择取消该目标，或用另一个目标抢占它。

动作消息定义的结构体现了这些组成部分：

```text
int32 request
---
int32 response
---
int32 feedback
```

由于建立和监控连接存在开销，ROS 2 中的动作适合耗时较长的过程。
如果只需要耗时较短的远程过程调用，可以考虑改用[服务](About-Services.md)。

动作通过动作名称标识。动作名称的形式与话题名称相似，但两者位于不同的命名空间。

一个动作由动作服务端和动作客户端两部分组成。

<span id="action-server"></span>

## 动作服务端

动作服务端接受远程过程请求，并执行相应的操作。
它还负责在执行过程中发送反馈，并响应取消或抢占请求。
例如，下面是一个计算斐波那契数列的动作接口：

```text
int32 order
---
int32[] sequence
---
int32[] sequence
```

动作服务端接收该消息，计算到 `order` 指定位置的数列，并在计算过程中提供反馈，最后通过 `sequence` 返回完整结果。

!!! note "说明"

    同一个动作名称应始终只对应一个动作服务端。
    如果多个动作服务端使用相同的动作名称，客户端请求会由哪一个服务端接收，其行为没有定义。

<span id="action-client"></span>

## 动作客户端

动作客户端请求远程动作服务端代为执行某个过程。
在上面的例子中，动作客户端创建包含 `order` 的初始消息，等待服务端计算并返回数列，同时接收计算过程中的反馈。

与动作服务端不同，同一个动作名称可以供任意数量的动作客户端使用。
