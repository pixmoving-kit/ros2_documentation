# 平台支持级别

平台被定义为OS,架构,以及 RMW 执行的组合. 如果一个平台/操作系统提供了多个变体,(例如Ubuntu桌面) ROS distro将会为桌面变体构建,除非另有说明. ROS 2 变体的定义在 [REP 2001号](https://www.ros.org/reps/rep-2001.html).

<span id="tier-1"></span>

## 第1级

第一级平台经常接受我们的单位测试套件和其他测试工具,包括连续的集成工作、夜间工作、包装工作和性能测试。在这些平台中发现的错误或错误被开发团队优先纠正。第一级平台中发现的重大错误会影响发布日期,我们努力在新版本发布前解决第一级平台中已知的高度优先错误。

<span id="tier-2"></span>

## 第二级

第二级平台需要定期进行CI测试,测试既要进行建设,也要进行测试,结果可以公开查阅。预计CI至少要在对ROS分发现状进行相关修改后一周内运行。软件包级二进制软件包可能不提供,但鼓励提供可下载的已建工作空间档案。第二级平台发布的产品版本中可能存在错误。第二级平台已知的错误将在资源可用性允许的情况下加以解决,在新版本发布之前可能或不会得到纠正。一个或多个实体应致力于继续支持该平台。

<span id="tier-3"></span>

## 第3级

第三级平台是指社区报告显示发布功能的平台. 开发团队不运行单元测试套件,也不在第三级平台上进行其他测试. 安装指令应当可用并更新,以便将平台列入这一类别. 社区成员可以向这些平台提供援助.
