# 发行版开发流程

ROS 2 的每次发行都经过了超过一年的开发过程,开始于上一份发行发行之前. 下面是对这一开发过程的高层观点,对于这个过程的项目没有具体的到期日,但一般来说,更早的项目应该在以后的项目完成之前完成.

关于这一过程的进展,请参看该版的文件页。

| 项目 | 页:1 |
|----|----|
| 去找老大罗素 | “ROS Boss”是负责通过开发、发布、更新和EOL生命中的各个阶段来进行分发的负责人。 他们是从开放机器人公司内部ROS 2团队中挑选出来的。 |
| 运行程序以选择分发名称 | ROS Boss利用社区及潜在命名冲突等来源的输入, |
| 创建分发文档页面 | 每次分发都有一个文件页,列出其生命统计,如计划发布日期、EOL日期以及自上次发布以来的重大变化。 |
| 设定发布时间表 | 发布日(通常是世界龟日)前的最后几周是繁忙的、充满最后期限的,比如何时冻结默认的《房管公约》的实施。 这些最后期限必须提前很多时间来规划。 |
| 制作路线图 | 虽然ROS的每个贡献者都有各自计划的每次发行的功能,但我们努力维持我们期望在发行中看到的新功能和重大变化的总体路线图,ROS Boss和开放机器人的ROS 2开发团队的组长与ROS 2 TSC和其他感兴趣的方面合作,以制定在可用时间内可以实现的路线图,满足ROS社区的需要. |
| 宣布路线图 | 计划特征清单和重大变革通过一个GitHub问题公开,该问题将跟踪路线图中每个项目的开发进度。 当然,这并不意味着路线图目前已经固定下来,因为发展计划可能改变,而且我们总是(而且经常)欢迎新的贡献,即使这些贡献不在计划中的路线图上。 |
| 设定目标平台和主要依赖关系 | 目标平台在操作系统、分发和版本方面,必须提前足够时间进行基础设施开发工作(如建设农场中的支持),同样,每个主要依赖的版本(Python版本、编译器、Eigen版本等)也必须固定。 [REP-2000号报告](https://reps.openrobotics.org/rep-2000/). |
| 向建设农场增加平台支持 | 建材农场是支持ROS 2 配送的基础设施的关键部分,它提供持续的集成设施,帮助我们保持质量,它构建了社区所依赖的二进制套件,以避免从源头构建ROS 2 和套件。如果目标平台与之前的ROS 2 配送不同,那么就必须为建材农场增加必要的支持。 |
| 委员会的标志和有关艺术品 | 每个ROS 2 发行(和 ROS 发行!)中都有一个很受喜爱的部分是标志,该标志是由专业艺人根据所选择的发行名称委托制作的,基于该标志,还制作了其他的艺术品,如龟兹图标. |
| 为分发创建邮件列表 | 对于发布批评性公告来说,必须建立邮件列表,以联系对分发信息感兴趣的人,比如他们的包裹未能在建设农场上建立二进制. |
| 创建测试大小写 | 随着开发过程进入最后几个月,测试工作将认真开始,开发最后阶段将使用的整合测试案例必须制作出来,并提供给负责实施这些案例的释放小组。 |
| 宣布即将进行的RMW冻结 | RAMW冻结是新发行版默认的RAMW执行功能被冻结的点,这使得开发者有一个稳定的目标来测试他们的软件包,这对客户端库开发者来说尤其重要,他们需要知道RAMW层的哪些特性可供客户端库使用. |
| 升级依赖软件包 | 软件包由ROS所依赖,而不是ROS软件,而且平台软件包管理器(例如Ubuntu的能力)无法提供,所谓的“供应商包”必须更新到REP-2000规定的版本(或适当的版本,对于REP-2000中未列出的版本),这一点对Windows尤其重要。 |
| 创建详细的释放计划 | 对开发过程的最后两个月进行规划,从而产生详细的测试计划、必须何时提供某些软件包的时间表等等,从而能够确定发布过程中的各个步骤与找到执行其中每一个步骤的人之间的依赖关系。 |
| 冻结RMW | 落实《保护移徙工人公约》目前已经冻结,从理论上讲,现在可以进行详尽的测试,以确保在发布日前正确运作。 |
| 宣布即将实行的全面冻结 | 在RMW执行冻结之后的下一次冻结是整个发行过程的冻结。 这是ROS核心软件包成为特性冻结的点,让非核心软件包的开发者有一个稳定的目标来测试他们的软件包,并且给发行测试者一个在测试后不会改变的东西。 |
| 冻结分发 | 从这一点开始,任何核心ROS包都无法添加新的特性,只有对开发的集约化测试阶段发现的(可变)bug进行bug修正才能融入代码库中,这意味着Rolling Ridley是有效冷冻,温和的. |
| 宣布即将到来的分支 | 从Rolling Ridley发行的ROS 2新版本的分支化是一个重要时刻,值得准备. |
| 即将宣布的β | 当分布进入β时,它准备由ROS社区进行更广泛的测试,这种β在分布从Rolling Ridely分支开始后不久发生. |
| 来自罗林瑞德利的分行 | 新的ROS 2发行是通过从Rolling Ridley制作一个新的分支创建的,实际上,新的发行是在此时诞生的,同时,Rolling Ridley已经摆脱了开发过程,可以继续进入未来,再次获得新的功能. |
| 向 CI 添加分发 | 连续集成系统被更新,以便使用新发行的分支和核心ROS软件包来构建。 这意味着软件包开发者可以运行CI来代替新发行的软件包,而不是Rolling Ridley。 |
| 开始建造临时测试柏油丸 | 精锐的测试者团队会把新的分布通过速度来进行测试,需要一些不需要不断从源头编译ROS 2来测试的东西。 建造农场被用来生产一套包含一定时间的分布的焦油球,供测试者测试。 |
| 增加分发文件 | 关于分发情况的详细文件,如自上次分发以来发生的重大变化,已添加到ROS 2文件网站。 |
| 宣布β | 发行量的β释放,并且邀请整个ROS社区参与测试(对于还没有这么做的人来说 ) 。 此时,测试者越多,因为发行量需要尽可能地通过一系列方案才能在发行之前找到虫子。 |
| 最后发行准备 | 由于新发行进入了绝对完全冻结的阶段,最终准备了发行。这些包括利用建材农场生产二进制包,这样就可以释放一些东西。 |
| 发布 | 大型的一天,如果一切都计划好了的话,正好是5月23日的世界海龟日。 发行的二进制套件在发行存储器中提供,并发布公告。 各方举行,ROS 2开发团队休息时间很早。 |
