# 发行版开发流程

每个 ROS 2 发行版都要经历一年多的开发过程，而且在上一发行版发布之前就已启动。下面概述这一流程。各项工作没有固定的截止日期，但通常需要先完成前面的事项，再完成后面的事项。

某个具体发行版的进展，请查看其文档页面。

| 工作事项 | 说明 |
| --- | --- |
| 确定发行版负责人（ROS Boss） | ROS Boss 负责引导发行版走过开发、发布、更新和停止支持的整个生命周期，由 Open Robotics 内部 ROS 2 团队选出。 |
| 组织发行版命名 | 负责人统筹命名流程，参考社区意见，并考虑潜在的名称冲突。 |
| 创建发行版文档页面 | 每个发行版都有文档页，列出计划发布日期、支持终止日期，以及相对于上一版本的重要变化等关键信息。 |
| 确定发布时间表 | 正式发布前的最后几周通常非常繁忙，充满各种截止日期，例如默认 RMW 实现的冻结时间。发布日通常是世界海龟日，相关安排必须提前规划。 |
| 制定路线图 | 每位贡献者都有自己的功能计划，同时项目也需要整体路线图，列出预期的新功能和重要变更。ROS Boss 与 Open Robotics 的 ROS 2 开发团队负责人协同 ROS 2 TSC 及其他相关方，制定能够按时实现并满足社区需求的路线图。 |
| 公布路线图 | 通过 GitHub issue 公布计划中的功能和重大变更，并跟踪各项工作的开发进度。路线图并非就此固定：计划可能变化，也始终欢迎未列入计划的新贡献，实际开发中这种情况很常见。 |
| 确定目标平台和主要依赖 | 提前确定操作系统、发行版及其版本，让构建农场支持等基础设施开发能够展开。同时确定 Python、编译器、Eigen 等主要依赖的版本，并更新 [REP 2000](https://reps.openrobotics.org/rep-2000/)。 |
| 为构建农场添加平台支持 | 构建农场提供持续集成以保证质量，并生成社区使用的二进制包，使用户无需从源码构建 ROS 2 及软件包。如果目标平台不同于上一发行版，必须添加相应支持。 |
| 委托设计标志及相关图像 | 每个 ROS 2 和 ROS 发行版的标志都深受喜爱。根据发行版名称委托专业艺术家设计标志，再据此制作 turtlesim 图标等其他图像。 |
| 创建发行版邮件列表 | 用于发布重要公告，并联系关心发行版的人员，例如通知维护者其软件包在构建农场生成二进制包时失败。 |
| 创建测试用例 | 开发进入最后几个月时，测试全面展开。需要准备开发后期使用的集成测试用例，并交给负责执行测试的发布团队。 |
| 预告 RMW 冻结 | 此时冻结新发行版默认 RMW 实现的功能，为开发者提供稳定的测试基础。客户端库开发者尤其需要确定 RMW 层将提供哪些功能。 |
| 升级依赖软件包 | ROS 依赖但并非 ROS 软件、也无法通过平台包管理器（例如 Ubuntu 上的 aptitude）获取的第三方封装包，即 vendor package，必须更新至 REP 2000 指定的版本；未列出的依赖则选择合适版本。这一点在 Windows 上尤其重要。 |
| 制定详细发布计划 | 规划开发流程的最后两个月，包括详细测试计划、特定软件包必须就绪的时间等，以发现发布步骤之间的依赖关系，并安排各步骤的执行者。 |
| 冻结 RMW | RMW 实现进入功能冻结。理论上，此后可以进行全面测试，确保发布日正常工作。 |
| 预告整体冻结 | RMW 之后将冻结整个发行版。核心 ROS 软件包停止添加功能，为非核心软件包开发者提供稳定的测试基础，也避免发行版测试人员刚测完的内容立即改变。 |
| 冻结发行版 | 此后所有核心 ROS 软件包都不能再添加新功能，只接受密集集成测试中不可避免发现的缺陷修复。这实际上意味着 Rolling Ridley 暂时冻结。 |
| 预告创建分支 | 从 Rolling Ridley 为新 ROS 2 发行版创建分支是重要时刻，应提前做好准备。 |
| 预告 beta 版本 | 进入 beta 意味着可以开展更广泛的社区测试。通常在从 Rolling Ridley 创建分支后不久进行。 |
| 从 Rolling Ridley 创建分支 | 创建新分支后，新发行版便正式诞生。与此同时，Rolling Ridley 解除本轮发布流程的限制，继续滚动开发并接收新功能。 |
| 将发行版加入 CI | 更新持续集成系统，使其支持使用新发行版的分支和核心软件包构建。软件包开发者即可针对新发行版而不是 Rolling Ridley 运行 CI。 |
| 开始生成中间测试归档包 | 测试团队需要可直接测试的内容，避免不断从源码编译 ROS 2。构建农场会生成某个时间点的发行版归档包，供测试人员使用。 |
| 补充发行版文档 | 将相对于上一发行版的重要变化等详细信息加入 ROS 2 文档网站。 |
| 发布 beta | 发布 beta 版本，邀请整个 ROS 社区参与测试。此时测试人员越多越好，需要覆盖尽可能广泛的使用场景，在正式发布前发现缺陷。 |
| 最终发布准备 | 发行版进入全面冻结阶段后，完成最后准备，例如通过构建农场生成待发布的二进制包。 |
| 正式发布 | 如果一切按计划进行，发布日就是 5 月 23 日世界海龟日。将二进制包放入发布仓库并发布公告。大家举行庆祝活动，ROS 2 开发团队也可以享受应得的休息。 |
